# Classroom Compass

Classroom Compass generates lesson resources from teacher material, then uses student work later for an instructional diagnostic and targeted follow-up.

The sample path remains available without credentials. Live analysis and the four generated assets require an OpenAI API key and the local Node server.

## What changed

- The browser now uploads material to a same-origin server, never directly to OpenAI.
- The server sends lesson material as a file input to generate resources. It sends lesson material plus student work only when the teacher requests a diagnostic.
- The assistant answers from the live diagnostic held only in the current server session.
- Asset generation returns a real editable PPTX, an MP3 generated by text-to-speech, a Markdown practice set, and an ICS calendar.
- OpenAI file objects are deleted after each diagnostic. The server keeps diagnostics only in memory unless optional Supabase persistence is enabled.

## Local setup

1. Install Node.js 20 or newer.
2. Install the dependencies:

~~~
npm install
~~~

3. Copy the environment template and add an OpenAI project key:

~~~
Copy-Item .env.example .env
~~~

Set OPENAI_API_KEY in .env. Create and manage project keys in the OpenAI platform. Do not put this key in app.js, index.html, or a frontend hosting provider's public environment variables.

4. Start the app:

~~~
npm run dev
~~~

5. Visit [http://localhost:3000](http://localhost:3000).

## Live flow

### 1. Create resources from the lesson

1. Upload one lesson (PDF, PPT/PPTX, TXT, or MD).
2. Use **Lesson Studio** to create and download the PPTX, MP3, Markdown practice set, and ICS plan.

### 2. Diagnose student work afterwards

1. Add at least one student submission (PDF, TXT, or MD) alongside the uploaded lesson.
2. Click **Analyze class work**. The dashboard changes from DEMO DATA to LIVE ANALYSIS.
3. Ask the Compass chat questions grounded in the returned diagnostic. Re-run the Lesson Studio resources if you want them tailored to the diagnosed need.

Use the sample lesson and three sample submissions for a credential-free UI walkthrough. They intentionally stay in demo mode and do not call an API.

## Privacy and classroom data

Remove student names and other direct identifiers before upload when possible. The app renames files to neutral names before sending them to OpenAI, but it cannot remove identifiers embedded in the document contents. Do not upload records that your institution does not permit you to share with the selected providers.

The server sets store: false for model responses and deletes the temporary OpenAI file objects after processing. Review your institution's data policy and the [OpenAI API data controls documentation](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint) before a classroom deployment.

## Optional Supabase persistence

Without Supabase configuration, sessions exist only in server memory and disappear when the server restarts. To store diagnostics remotely, create a Supabase project and run this SQL in its SQL editor:

~~~
create table public.compass_sessions (
  id uuid primary key,
  created_at timestamptz not null,
  analysis jsonb not null
);

alter table public.compass_sessions enable row level security;
~~~

For this server-only prototype, add the project URL and **service role key** to .env:

~~~
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
~~~

Never expose the service role key in the frontend. Before deploying to multiple teachers, add authentication and row-level policies keyed to the authenticated teacher or school. The current prototype intentionally does not persist original uploads or student names.

## Deployment notes

Deploy this as a Node service that preserves the server boundary, such as Render, Railway, Fly.io, or a server-capable Vercel deployment. Static-only hosting will not run server.js. Set the same environment variables in the host's secret manager, enforce authentication before enabling real student uploads, and set a server-side upload/rate limit appropriate to the school.

## API design

| Route | Purpose |
| --- | --- |
| GET /api/health | Reports whether OpenAI and optional persistence are configured, without exposing values. |
| POST /api/diagnose | Accepts multipart lesson and submissions, returns a structured classroom diagnostic. |
| POST /api/chat | Uses the in-memory diagnostic session for an evidence-grounded teacher response. |
| POST /api/assets | Accepts lesson material, optionally applies a diagnostic, and produces PPTX, MP3, Markdown, and ICS download payloads. |

The implementation uses the OpenAI Responses API with file inputs and structured JSON. The API supports text, image, and file inputs; the app supplies the current diagnostic to each chat request so responses can remain session-only. [OpenAI Responses API reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

Speech generation uses gpt-4o-mini-tts through the Audio Speech endpoint. Its input limit is 4,096 characters and it can return MP3. [OpenAI audio speech reference](https://developers.openai.com/api/reference/cli/resources/audio/subresources/speech/methods/create)
