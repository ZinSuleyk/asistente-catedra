# Classroom Compass

Classroom Compass generates a lesson deck, audio recap, and PDF exercise set from teacher material, then uses student work later for an instructional diagnostic and targeted follow-up.

The sample path remains available without credentials. Live analysis and the four generated assets use one OpenRouter API key and the local Node server.

## What changed

- The browser now uploads material to a same-origin server, never directly to OpenRouter.
- The server sends lesson material as a file input to generate resources. It sends lesson material plus student work only when the teacher requests a diagnostic.
- The assistant answers from the live diagnostic held only in the current server session.
- Asset generation returns a real editable PPTX, an MP3 generated by text-to-speech, and a PDF practice set.
- The server sends documents only with the request and keeps diagnostics only in memory unless optional Supabase persistence is enabled.

## Local setup

1. Install Node.js 20 or newer.
2. Install the dependencies:

~~~
npm install
~~~

3. Copy the environment template and add your OpenRouter key:

~~~
Copy-Item .env.example .env
~~~

Set OPENROUTER_API_KEY in .env. Create and manage keys in the OpenRouter dashboard. Do not put this key in app.js, index.html, or a frontend hosting provider's public environment variables.

4. Start the app:

~~~
npm run dev
~~~

5. Visit [http://localhost:3000](http://localhost:3000).

## Live flow

### 1. Create resources from the lesson

1. Upload one lesson (PDF, PPTX, TXT, or MD).
2. Use **Lesson Studio** to create and download the PPTX, MP3, and PDF practice set.

### 2. Diagnose student work afterwards

1. Add at least one student submission (PDF) alongside the uploaded lesson.
2. Click **Analyze class work**. The dashboard changes from DEMO DATA to LIVE ANALYSIS.
3. Ask the Compass chat questions grounded in the returned diagnostic. Re-run the Lesson Studio resources if you want them tailored to the diagnosed need.

Use the sample lesson and three sample submissions for a credential-free UI walkthrough. They intentionally stay in demo mode and do not call an API.

## Privacy and classroom data

Remove student names and other direct identifiers before upload when possible. The app uses neutral labels for student submissions, but it cannot remove identifiers embedded in document contents. Do not upload records that your institution does not permit you to share with the selected providers.

Review your institution's data policy and OpenRouter's provider logging/privacy controls before a classroom deployment.

## Optional Supabase persistence

Without Supabase configuration, sessions exist only in server memory and disappear when the server restarts. To store diagnostics remotely, create a Supabase project and run this SQL in its SQL editor:

~~~
create table public.compass_sessions (
  id uuid primary key,
  created_at timestamptz not null,
  analysis jsonb not null
);

alter table public.compass_sessions enable row level security;
~~~

For this server-only prototype, add the project URL and **service role key** to .env:

~~~
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
~~~

Never expose the service role key in the frontend. Before deploying to multiple teachers, add authentication and row-level policies keyed to the authenticated teacher or school. The current prototype intentionally does not persist original uploads or student names.

## Deployment notes

Deploy this as a Node service that preserves the server boundary, such as Render, Railway, Fly.io, or a server-capable Vercel deployment. Static-only hosting will not run server.js. Set the same environment variables in the host's secret manager, enforce authentication before enabling real student uploads, and set a server-side upload/rate limit appropriate to the school.

## API design

| Route | Purpose |
| --- | --- |
| GET /api/health | Reports whether OpenRouter and optional persistence are configured, without exposing values. |
| POST /api/diagnose | Accepts multipart lesson and submissions, returns a structured classroom diagnostic. |
| POST /api/chat | Uses the in-memory diagnostic session for an evidence-grounded teacher response. |
| POST /api/assets | Accepts lesson material, optionally applies a diagnostic, and produces PPTX, MP3, and PDF download payloads. |

The implementation uses OpenRouter Chat Completions with JSON output. PDFs go to OpenRouter as base64 file inputs, while PPTX files are text-extracted in the server before inference. [OpenRouter PDF inputs](https://openrouter.ai/docs/guides/overview/multimodal/pdfs)

Speech generation uses OpenRouter's compatible audio endpoint and your OpenRouter credits. The default model can be changed in .env. [OpenRouter TTS documentation](https://openrouter.ai/docs/guides/overview/multimodal/tts)
